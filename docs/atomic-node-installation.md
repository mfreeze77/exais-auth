## Executed behavior and failure handling

`node-image-build/atomic-password-session-02` builds the complete Dockerfile
with networking disabled for RUN steps and runs its installed image through the disposable atomic parent and
the actual Node/SMTP/React child. The child passes 15 HTTP/SMTP, 10 TLS and nine
Chromium behavior checks. The reset success screenshot was visually inspected.
All 22 synthetic fixtures are removed and the initially empty identity set is
restored. This lab never contacts the persistent source database.

The new missing-writer case runs the new Core JAR with the original PostgreSQL
plugin. Actual container file hashes prove that combination, alongside the
complete new pair and the original Core/plugin pair. The mismatched deployment
is live but not ready: HTTP 200 and 503 respectively. Correct-password sign-in
returns a generic HTTP 500 without access/refresh headers or authentication
cookies. The actual Core response is HTTP 503, `PASSWORD_SESSION_REJECTED`.
Its existing session remains usable and the engine's session inventory is
unchanged. A retry through the healthy writer creates exactly one session.

The test-only observer records 38 successful private password-session calls on
the healthy path and one rejected call on the missing-writer path. No legacy
session insertion call occurs. It leaves request/response bytes unchanged and
stores only bounded path/status/policy fields, never token or credential bodies.
This qualifies the explicit missing-provider deployment fault, not every plugin
loading, rolling-upgrade or storage-failure combination.

The first installed run failed because the observer's fixed status allowlist
converted `PASSWORD_SESSION_REJECTED` into `OTHER`. The recorded application
readiness and sign-in already failed closed. The observer was corrected without
changing product code; the full case then passed. Both original reports and
source snapshots remain preserved. The failed candidate was removed without
promotion. The corrected build reused all seven application/dependency layers.
