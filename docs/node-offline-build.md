## Resume commands and prerequisites

For an actual image-content change, from the repository root:

```powershell
python -B tools/build_node_client.py --name NEW_CLIENT_BUILD
python -B tools/build_node_runtime.py --name NEW_IMAGE_BUILD
python -B tools/verify_checkpoint_hygiene.py
```

The builder needs the existing owned Node image, pinned Node base, retained npm
cache, private Core/PostgreSQL lab, pinned Mailpit/Playwright images and existing
browser test dependencies. Names must be fresh and at most 54 characters. It
audits the previous dependency tree before building, so dependency-lock updates
need a separately reviewed update workflow. App-only harness work should use
the cached compiler/lab; it does not require rebuilding unchanged dependencies.

The Dockerfile requires the named build context `node_packages` pointing to
`.cache/node-packages`; an ordinary context-only `docker build` is insufficient.
The original cache was recovered from a now-retired image. The new image does
not retain npm's cache, so `--export-cache-only` cannot recreate it. The tested
`tools/run_node_bootstrap.py --name NEW_CACHE_ACQUISITION --mode online` path
now acquires missing locked archives directly; an offline run verifies retained
bytes without downloads. It requires the cached pinned Node base. Full first
image/fresh-extraction/identity-stack deployment remains **unqualified**; the
image orchestration still requires the previous owned image and private lab.
Do not delete the bounded host cache to repeat unchanged passing downloads.
